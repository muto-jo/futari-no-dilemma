# 『ふたりのジレンマ』Web版 仕様書

この文書が、ゲームのルールと作るものの正本です。ルールの数値と処理順は `reference/dilemma_c.py`(バランス調整に使ったシミュレーター)と一致させてください。食い違ったらシミュレーターが正しく、この文書を直します。

## 1. 何を作るか

夫役と妻役の2人で家事・育児を乗り切る、協力型のカードゲームのWeb版です。囚人のジレンマが下敷きで、「疲れたからお願い」「いいよー」と頼み合い、約束を守る夫婦が一番得をするように調整してあります。父親コミュニティでの遊びや、ワークショップの教材として使います。

- 配布方法: GitHub Pages(静的サイト)。サーバーは持たない
- 対象端末: スマートフォン優先。PCブラウザでも遊べること
- 言語: 日本語のみ
- 遊び方は3モード
  1. **1台で2人**(最優先): 1台の端末を2人で回して遊ぶ
  2. **AIと対戦**: 1人で、シミュレーターの戦略を移したAIと遊ぶ
  3. **オンライン対戦**: 2台の端末をP2Pでつないで遊ぶ(最後に実装)

## 2. ルール

### 2.1 構成

| 要素 | 内容 |
| --- | --- |
| 家事イベントカード | 30枚。重さ1・2・3が各10枚(`data/cards.json` の `events`) |
| 思春期カード | 1枚。出たら終盤に入る |
| 巣立ちカード | 1枚。出たらゲーム終了 |
| 約束カード | 1人3種類: 一緒にやる(`together`)/私がやる(`me`)/あなたに頼む(`you`) |
| 行動カード | 1人2種類: やる(`do`)/任せる(`delegate`) |
| 役割カード | 残業・実家ヘルプ。2人にランダムに1枚ずつ配る。各1回だけ使える |
| 家庭ゲージ | 初期値10 |
| 疲労トークン | 各自0から。公開情報 |
| 不満トークン | 各自0から。公開情報 |
| 記録 | 各自の自由時間・思い出・信頼(すべて得点) |

### 2.2 山札の作り方

1. 家事イベント30枚をシャッフルし、先頭20枚を山A、残り10枚を山Bにする
2. 山Bに巣立ちカードを加えてシャッフルする
3. 山札 = 山A + [思春期] + 山B
4. これで家事は20〜30ラウンド行われる。思春期の後(21ラウンド目以降)が終盤

### 2.3 ラウンドの流れ

各ラウンドは次の順に進みます。`w` はそのラウンドの家事の重さです。

1. **イベント公開**: 山札を1枚めくる
   - 思春期なら終盤フラグを立てて、もう1枚めくる(ラウンド数に数えない)
   - 巣立ちなら、ゲーム終了(2.6へ)
   - 実家ヘルプを持つ人は、ここで使える: `w = max(1, w - 1)`
2. **ダウン判定**: 疲労が7以上の人はダウン。このラウンドは家事ができない
3. **相談**: 自由会話。疲れた人は「お願いしていい?」と頼める(2.4)
4. **約束カード**: 各自1枚を伏せて出し、同時に公開する。ダウン中の人は「あなたに頼む」で固定
5. **行動カード**: 各自「やる」か「任せる」を伏せて出し、同時に公開する
   - ダウン中の人は「任せる」で固定
   - 残業を持つ人は、「任せる」を出すときに残業の使用を宣言できる(ダウン中は不可)。宣言したら効果の有無にかかわらず使用済み
6. **処理**: 2.5の表に従う
7. **睡眠とチェック**: 2.5の後半に従う

### 2.4 お願い(相談フェイズ)

- 疲労トークンは公開なので、頼まれた側は相手が本当に疲れているかを見て、受けるか断るかを決める
- 受けたら: 頼んだ側が「あなたに頼む」、受けた側が「私がやる」を出すのが合意の形
- 約束カードに拘束力はない。カードを出したあとに裏切ることもできる(その代償が約束破り)
- 「お願い成立」は、カードが「私がやる」と「あなたに頼む」で揃い、そのとおりに片方だけがやった場合のみ

### 2.5 処理

**やる/任せるの組み合わせごとの処理**

| 結果 | 家庭ゲージ | やった人 | 任せた人 | 信頼 |
| --- | --- | --- | --- | --- |
| 2人ともやる | +w | 2人とも思い出+w、疲労+ceil(w/2) | — | 2人とも約束が「一緒にやる」なら各自+1 |
| 片方だけ・お願い成立 | ±0 | 疲労+w | 休養(睡眠とは別に疲労−2)。自由時間なし | 各自+2 |
| 片方だけ・任せた人がダウン中 | −1 | 疲労+w。不満は付かない | なし | — |
| 片方だけ・任せた人が残業を宣言 | ±0 | 疲労+w。不満は付かない | 自由時間なし | — |
| 片方だけ・上記以外 | ±0 | 疲労+w、不満+1 | 自由時間+w | — |
| 2人とも任せる | −(w+1) | — | — | — |

「片方だけ」の4行は、上から順に判定します(お願い成立 > ダウン > 残業 > それ以外)。

**約束破り**: 約束が「一緒にやる」か「私がやる」なのに「任せる」を出したら、相手の不満を+2します。上の表の不満+1とは足し合わせず、そのラウンドに相手に付く不満は `max(既存の加算, 2)` にします。

**睡眠**: 2人とも `疲労 = max(0, 疲労 − 休養 − 1)`。休養はお願い成立で休んだ人だけ2、ほかは0。

**不満チェック**: 不満の加算を反映したあと、夫→妻の順に判定します。不満が4以上の人がいたら、不満を溜めさせた相手(causer)に対して:
- 思春期より前: **爆発**。causerの自由時間を半分(切り捨て)にし、不満を0に戻す
- 思春期より後: **離婚**。即座にゲーム終了(2.6)

**共倒れ**: 不満チェックのあと、家庭ゲージが0以下ならゲーム終了(2.6)。

### 2.6 終了と得点

| 終わり方 | 各自の得点 |
| --- | --- |
| 巣立ち・家庭ゲージ10以上(家族成功) | 満足度 + 15 |
| 巣立ち・家庭ゲージ9以下(完走) | 満足度 |
| 共倒れ | 2人とも0 |
| 離婚 | causerは−10、もう1人は0 |

- 満足度 = 自由時間 + 思い出 + 信頼 − 残った疲労
- 家族ランク(2人の合計): S 150以上 / A 110〜149 / B 60〜109 / C 0〜59 / 共倒れ・離婚はランクなし
- 家族成功のときは、個人の得点が高いほうを「今回のMVP」として表示する

## 3. アーキテクチャ

- **ゲームエンジンは画面から完全に切り離す**: `src/engine/` に、DOMにもネットワークにも依存しない純粋なTypeScriptの関数として書く。1台モード、AI戦、オンライン対戦、シミュレーションのすべてが同じエンジンを使う
- **状態は不変(immutable)**: `(state, input) => newState` の形。乱数は seed 付きのPRNG(mulberry32など)を状態に持たせ、同じseedと同じ入力なら同じ結果になること
- **フェイズを型で表す**: `event` → `consult` → `promise` → `action` → `resolved` → 次のラウンド、または `ended`
- **処理ログ**: 1ラウンドの処理結果(誰に何が何個付いたか、お願い成立、約束破り、爆発など)を構造化データで返し、画面のログ表示と振り返りに使う
- 約束を使わないAI戦略のため、エンジンは約束 `null`(約束カードを出さない)も受け付ける。人間のプレイヤーは必ず約束カードを選ぶ(未決事項 7.1)

## 4. 画面

スマートフォン縦向きを基準にします。

1. **タイトル**: ゲーム名、「1台で2人」「AIと対戦」「オンライン対戦」「ルール」
2. **準備**: プレイヤー名の入力(既定は「夫」「妻」)。役割カードの配布結果を表示
3. **ゲーム画面**: 常に見える場所に、家庭ゲージ、2人の疲労・不満(トークンの数が一目で分かる表示)、自由時間・思い出・信頼、終盤かどうか、残り山札の目安(終盤に入ったかだけで、正確な残り枚数は出さない)
   - イベントカード(名前・重さ・フレーバーテキスト)
   - フェイズごとの操作ボタン
   - 直近のラウンドの処理結果と、開閉できるログ
4. **結果画面**: 終わり方、家族ランク、各自の得点の内訳、MVP。振り返りの問い3つ(下記)。「もう一度」「タイトルへ」
5. **ルール画面**: 2章のルールを、遊ぶ人向けの言葉で短くまとめたもの

振り返りの問い:
- あなたが「お願い」を言い出せなかった場面はありましたか?
- 相手の疲労トークンに気づいたのはいつでしたか?
- 実際の家では、どのタイプに近いですか?

デザインの方針:
- 夫役と妻役に青とピンクのような性別を連想させる色を割り当てない。2人は中立な2色で区別する
- 説教くさくしない。約束破りや離婚が起きても、責める表現にしない
- 文字は大きめ、ボタンは指で押しやすい大きさにする

## 5. モード

### 5.1 1台で2人(ホットシート)

- 相談フェイズは画面に「相談してください」と出し、2人は口頭で話す。「相談終了」ボタンで次へ
- 約束カードと行動カードの選択は、1人ずつ順番に行う
  1. 「夫(名前)の番です。妻(名前)は画面を見ないでください」→「準備OK」
  2. 夫が選ぶ →「選びました。スマホを渡してください」画面(選んだ内容は表示しない)
  3. 妻も同じ手順
  4. 「2人とも選びました」→「同時に公開」ボタンで表示
- 選択の受け渡し画面では、前の人の選択が絶対に見えないようにする

### 5.2 AIと対戦

- 人間は夫役か妻役を選び、AIのタイプを選ぶ(タイプ名は対戦後に明かす「おまかせ」も用意する)
- AIのタイプは `reference/dilemma_c.py` の戦略から移植する。最低限このA〜F

| 表示名 | 元の戦略 | 説明(結果画面で明かす) |
| --- | --- | --- |
| A 思いやりさん | 思いやり | 疲れたら頼む、頼まれたら受ける、約束を守る |
| B 頑張りすぎさん | 頑張りすぎ | 頼まれたら全部受けるが、自分からは頼まない |
| C きっちり半分さん | 約束交代 | 毎回「今日は私、次はあなた」と約束する |
| D 黙ってお返しさん | しっぺ返し | 相談しない。前回あなたがしたことを返す |
| E ふざけ屋さん | ふざけパパ | 約束はするが、4回に1回破る |
| F 甘え上手さん | 甘え上手 | 毎回お願いしてくる。頼まれても断る |

- 相談フェイズのやり取り
  - 人間は「お願いする(休みたい)」ボタンを押せる。AIは元の戦略の accept 関数で受けるか決め、「いいよー、私がやる」か「ごめん、今回は一緒にやろう」と返す
  - AIの request 関数が真なら、AIから「疲れたからお願いしていい?」と聞く。人間は「いいよー」「ごめん」で答える
  - 2人とも休みたい場合の扱いは `dilemma_c.py` の play() に合わせる(疲労が多いほうが頼む。同じなら乱数で決める)
  - 合意の結果からAIの約束カードを決める(成立なら 私がやる/あなたに頼む、不成立なら一緒にやる、約束を使わない戦略なら null)。人間は約束カードを自由に選べる(合意と違うカードを出してもよい)
- AIの行動は元の戦略の act 関数で決める
- AIの役割カード: 実家ヘルプは最初に重さ3が出たときに使う。残業は、ダウンしていないときに最初に「任せる」を出したラウンドで使う
- AIの考えた内容は人間に見せない。AIの約束と行動は、人間が選び終えてから同時に公開する

### 5.3 オンライン対戦

- 接続は WebRTC のP2P。ライブラリは **Trystero を `0.26.0` に固定**して使う。仲介(signaling)の方式とAPIは、そのバージョンのREADMEを読んで決めること。既定の方式でつながらないときに別の方式へ切り替えられるようにする
- 部屋を作った側がホスト。6文字程度の合言葉を表示し、相手はそれを入力して入る
- 部屋を作るときに、相談フェイズの「あり/なし」を選べる。「なし」では相談をせずに約束カード → 行動カードへ進む(ルールの処理は同じ)
- 名前の初期値は、候補(あきら・かいと・さとる・たつや・なると・あい・かな・さき・たえ・なみ)から役に関係なくランダムに選ぶ。自分で入れた名前が保存されていればそれを使う。2人の名前が同じなら、ゲストの名前に「2」を付ける
- ゲームの状態はホストが持ち、ホストのエンジンで処理して、結果を相手に送る
- 約束カードと行動カードは **コミット&リビール** で送る: まず `SHA-256(選択 + ランダムなnonce)` だけを送り、両方のコミットが揃ったら選択とnonceを送って検証する。どちらの端末も、相手の選択を先に知ることはできない
- 相談フェイズ用に、定型ボタン(「お願いしていい?」「やるよー」「ごめん、無理」)と短い自由入力チャットを付ける。音声通話は別のアプリで、と案内する
- 切断時は、再接続を試みて、だめなら結果を保存せず終了する

## 6. 品質

### 6.1 エンジンのテスト(Vitest)

- 2.5の処理表の各行、約束破り、睡眠、爆発、離婚、共倒れ、家族成功の判定を、それぞれ単体テストで確認する
- 山札の構成(家事30枚、思春期が21枚目、巣立ちが22〜32枚目)を確認する

### 6.2 シミュレーションでの一致確認

`npm run sim` で、移植したAI戦略同士の総当たり(各組100戦)を実行できるようにする。乱数列はPythonと違うので完全一致はしないが、次の目安に収まることをテストで確認する(`reference/simulation_results_trust_1_2.txt` が元の結果)。

| 確認項目 | 目安 |
| --- | --- |
| 総当たりの平均点1位 | 思いやり |
| 思いやり同士 | 家族成功100%、2人の合計 159〜179 |
| しっぺ返し同士 | 家族成功95%以上、2人の合計 98〜118 |
| 約束交代同士 | 家族成功100%、2人の合計 120〜140 |
| ふざけパパ同士 | 離婚 55〜77% |
| 常に裏切り同士 | 共倒れ100% |

外れた場合は、エンジンかAIの移植に誤りがある可能性が高い。数値を合わせるためにパラメータを変えてはいけない。

役割カードは、エンジンでは 2.1 のとおりランダムに配る。`dilemma_c.py` では残業が常に夫なので、`npm run sim` と上の確認は既定でその割り当て(残業=夫、実家ヘルプ=妻)で行う。`npm run sim -- --roles=random` でランダムに配った場合も見られる。

### 6.3 その他

- 外部への送信はオンライン対戦のP2P通信だけ。アクセス解析や広告は入れない
- 保存するのはブラウザのlocalStorageに設定(プレイヤー名など)だけ。使えない環境でも動くこと

## 7. 未決事項(実装中に判断が要ったら、ユーザーに確認する)

1. 約束を使わないAI(しっぺ返しなど)は、物理カード版では必ず約束カードを出すルールと食い違う。Web版では「約束なし」と表示する案で進めてよいか → **決定**: 「約束なし」と表示する
2. 家族ランクの境目は暫定値。テストプレイで変える可能性がある
3. カードのイラストは当面なし(文字と色だけ)
